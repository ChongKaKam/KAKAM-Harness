# 对话 Harness

从升级后新建一个对话即可使用 Harness。每个新对话有自己的工作区，可以隔天继续工作。组内其他对话只读得到用户明确开放的版本。历史对话仍可查看，提交新问题请使用新对话。应用保留原账户、模型授权、Skill 库、Search 配置和历史数据。旧消息、旧 Memory 条目、旧偏好或历史产物都不会自动进入新工作区。

## 从问题到回答

用户提交问题后，聊天服务验证身份、模型、工具和会话并发额度，在 SQLite 事务中保存本轮消息和首笔用量占位，返回 HTTP 202。受理记录将提交 UUID、所属会话和规范化请求内容的 SHA-256 指纹绑定。同一会话重发相同 UUID 会返回原回答 ID。内容有变化时回执也会带上 `replayedWithDifferentContent: true`，保留原受理结果。跨会话复用或重发已被替换的回答返回 409。服务端继续执行，浏览器另行订阅 SSE。同一会话同时一个活动回答，每账户默认五个。浏览器重新订阅时用首帧快照替换本地消息。

新执行器读取当轮可用的工作区资料和 Skill，复用现有历史压缩、extensions 注册表及Responses 与 Anthropic Messages 两种回答协议。普通知识问答先解释原理，用户明确要求接续方案时再按项目资料展开。真正发起主模型、辅助模型或图片模型调用前，均检查当前用户授权；Token 只采用提供方报告的值。提交入口、执行器和工作区工具分别见 [chat/server.ts](../src/features/chat/server.ts)、[execute.ts](../src/features/harness/execute.ts) 和 [tools.ts](../src/features/harness/tools.ts)。

主模型的上下文容量按来源中保存的具体模型配置。历史压缩在搜索前准备一次，每次实际发送再把当轮工具定义、结果、补充输入和输出预留一起核对。长会话的 1M 窗口设置、自动压缩阈值和估算限制见[上下文管理](CONTEXT_MANAGER.md#自动压缩如何改变请求)。

**搜索与补查。** Off 跳过搜索。Auto 沿用 LLM 或 LLM + Jev 的需求判断，On 直接规划检索词。同一问题的不同词条可并行检索，来源按 URL 去重。辅助模型可以按需使用有权限的工作区资料生成词条，Perplexity 收到检索词及结果条数等参数。部分查询失败时，回答使用已取得的来源并指出未核实部分。若首次查询全部正常返回但没有可用来源，且尚有词条额度，支持再规划一次不同的词条。明确的 HTTP 429 在允许时间内可有限重试；超时、断流等回执未知的请求不会自动重发。

对于无需 Skill 会话或强制产物的普通问答，查询较慢时可另用已授权的主模型先写简短的已知部分。检索结束后，核实结果、修正和来源链接追加到原回答，两次模型调用分别计量。没有证据时直接说明待核实项。配置或授权错误在受理前提示；已受理任务中的搜索或工作区预载失败时，尽可能用其余可用材料作答。执行边界见 [Search](../src/features/search/server.ts) 和 [初步回答](../src/features/harness/search-preview.ts)。

**补充与停止。** 生成中的输入框可以向当前助手消息「发送补充」。服务端先登记“已收到”，在下一次可控的模型调用采用后标记“已应用”。正在流式输出的调用会完成当前正文，后续调用处理补充。运行期间明确的发布和授权口令则由服务端直接处理，回执保存在本轮补充记录。需要立即停止时使用原停止按钮。搜索、工具、正文、补充和错误的实际状态可在回复的进度行展开查看。

**等待用户决定。** 当任务需要用户选择时，模型可以用 `workspace_ask` 提出问题并给出初步建议和理由。缺少依据时可以只提问，也兼容原有的仅含 `question` 的调用。问题和建议会随本轮回复保存。用户可以直接输入自己的答案，或用「用建议起草回复」把建议放入输入框，修改并发送后才作为用户答复继续下一轮。「必须产物」模式需要确认交付物时，进度行显示「等待补充产物需求」，下方的产物卡保留具体问题。

**等待授权。** B 在生成中向 A 申请一份资料，可以先返回已完成的独立工作。待审申请保存在 SQLite，结束这次生成后释放并发名额。用户从 A 或 B 的授权卡处理具体申请；尚未选定的私有文件需回到 A 选择。批准时，目标任务仍运行则在可用步骤接收授权。原生成已结束则在 B 发起关联的后续回复，复用原问题和已保存历史；授权记录保留原任务 ID。重复提交同一决定或继续同一批准结果不会重复执行。当前权限、会话限额等条件暂不允许继续时，批准仍保存，用户可以从卡片再次继续。拒绝后同一申请保留原决定。

**断线与重启。** 浏览器锁屏、离页或丢失 SSE 只断开观察端。服务进程退出会中断它持有的上游调用。关机时等待任务保存，异常重启将遗留的 streaming 回复标为中断，保留已写入的正文、来源、调用用量、文件及独立的待审申请。用户手动重试末轮会启动新的尝试。上游流、付费调用和工具协议的私有续接数据均不会跨进程自动重放。

## 工作区、文件与个人偏好

在新聊天中打开「对话工作区」可切换「文档」「访问授权」「个人偏好」。分组表示同一账户下的项目。每次读取都检查当前用户、来源、目标、分组成员关系以及具体版本。

| 资料                          | 读取时机与访问范围                               | 写入者及生命周期                                                                                                                          |
| ----------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 会话 `AGENTS.md`、`MEMORY.md` | 默认读取当前会话这两份短文档                     | 新会话建立时初始化。Agent 可维护私有记忆，记录决定、暂定想法、待核实问题与变化原因                                                        |
| 项目 `AGENTS.md`              | 当前会话属于对应分组时载入                       | 用户在项目内编辑，分组中的新会话沿用该项目规则                                                                                            |
| 私有正式文档、交接草稿        | 本会话按需读取；创建时保留在来源会话             | 用户可直接编辑，也可提出明确的建档或修改请求。更新提交基础版本，保留文件 ID 和不可变旧版；版本冲突返回 409                                |
| 项目已发布版本                | 同一账户、当前属于该项目的会话可按需读取         | 用户在来源会话审阅、编辑后发布，并可勾选同时开放的具体文件版本。整次发布原子保存，草稿后续修改不更新已发布内容                            |
| 单独授权版本                  | 仅指定的目标会话可读，目录默认使用已获准的固定版 | 用户审批绑定来源、目标、用途、任务和版本。预授权还可指定目标对话下一次匹配的请求，24 小时到期，仅能消费一次。其他会话和后续版本需独立授权 |
| 新个人偏好                    | 明确纳入后供本账户新会话使用                     | 创建或修改正文进入待纳入，确认记录真实时间。撤出后停止载入。偏好管理和历史 Memory 使用独立存储                                            |
| 真实产物                      | 按私有来源、项目发布或指定版本授权处理           | 目录版本关联实际文件字节。临时文件过期或删除后失去可读性。详细保留规则见[产物契约](LLM_PRODUCTION.md#空间与保留时间)                      |

未开启工具调用的模型成功作答后，宿主仍可按明确的“记住……”请求更新当前会话的 MEMORY.md，或按“添加个人偏好：……”创建待纳入候选；这两种写入均不额外调用模型。若记忆文档已满，正文会保留，回执说明写入失败的原因。

工作区正文以用户级参考材料进入主模型上下文。用于日常聊天的短文档限制为每份 8000 字符，普通文档每版最多 100000 字符。工作区文本版本、发布副本和个人偏好按账户计入 16 MiB 容量；个人偏好每条最多 1000 字符，同时纳入最多 64 条、合计最多 8000 字符。二进制产物仍按产物空间的文件和账户限额管理。工作区不复制未获授权的其他会话正文。Context Manager 观察器保留工作区工具名称，用占位说明替代参数与返回值，自动加载的工作区正文从请求快照中省略。读取文档时重新校验当前权限。先前已展示给用户的问答仍保留在聊天历史中。

例如 A 可以先私下写一份选型对比，再将交接笔记发布给整个项目。若对比材料仅适合 B，发布笔记时不勾选它，在 B 用途明确的申请中选择对比文档 v3。B 可引用 v3；A 隔天修改的 v4 仍只在 A。移出项目时重新检查可读范围。已经发布的项目条目留在原项目；删除原会话也保留项目发布快照。删除项目会清理相应发布与访问记录。转交外部应用用的 Context Manager hand-off 是另一项显式导出操作，详见[上下文管理](CONTEXT_MANAGER.md)。

**更新到项目。** 来源会话中只有一份尚未发布当前版本的正式文档或交接草稿时，用户直接发送「更新到项目」即发布该版。有多份时会列出候选，用户可指定「更新『方案.md』v2到项目」。这个简写只选择正式文档和交接草稿，会话记忆、指令和产物仍需逐份明确选择。

**直接分享给一个对话。** 在来源 A 的「访问授权」选择「直接分享版本给一个对话」，选 B、文件和版本，预览后点击「分享此版本」。B 的文档目录立即可见；直接分享本身没有待处理任务，也不会发起模型调用。也可以在 A 输入「分享“对比.md”v1给“B”」。若 B 随后通过项目发布获得同一文档的 v2，目录默认展示最新可读的 v2，仍可明确打开先前获准的 v1。只收到项目发布的 C 仍只能读 v2。

## 工具循环与协议边界

主回答、搜索辅助 LLM、摘要及模型工具测试仅使用 OpenAI Responses 或 Anthropic Messages。宿主逐轮选择可用工具、核对权限和预算、执行调用，并按调用 ID 返回真实结果。Responses 的 `function_call_output` 和 Messages 的 `tool_result` 在各自适配器中编码。对于同批多个工具请求，宿主在第一项执行前核对整批名称是否都在本轮声明内。执行时逐项检查剩余额度、参数、资源权限和版本。达到次数上限时保留此前已经完成的产物。Jev 提供独立的搜索决策，Embedding、图片以及外部 SDK 网关均有单独的接口。

参考对象是本地资料集记录的 Claude Code **2.1.107**。原客户端的分支来自打包代码静态摘录；同目录 Panda 是独立的 Python 重实现，其验证记录使用本地模拟服务。

| 对照项           | Claude 资料中的实现                                                                                | Drift Space 的选择                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 何时执行工具     | `SfY` 支持在流中调度已收齐的工具块，也有等这一轮收齐再调度的分支。Panda 的 `Engine.run` 使用后者。 | 正文可以流式显示。两个协议都要收齐工具轮次，宿主才会执行工具。收到一半中断时不会因此产生文件写入。                         |
| 谁决定执行与共享 | `hMY` 在执行前校验输入与权限，结果关联原工具调用。                                                 | 宿主先核对本轮声明，再由具体工具校验操作。A 申请读 B 的文件时，授权由用户给出，绑定目标和版本。                            |
| 哪些工作可并行   | `CMY/Z38` 根据工具与输入是否可安全并行来分组，按调用顺序应用状态变更。                             | 同一问题的 Perplexity 查询可以并行。工作区和产物工具按模型调用顺序执行，文件修订和发布有确定顺序。                         |
| 压缩后如何续接   | `RC6` 把摘要与按预算选择的文件、任务和计划等资料重新组合。                                         | 历史可以压缩，当前获准使用的工作区规则、会话记忆、Skill 和文件访问规则由宿主另行处理。每次实际发送继续计算工具及输出预留。 |

原始摘录可按资料集中的 `evidence/loop/loop-findings.md` 以及 `evidence/state/execution-findings.md` 的 `STATE-hMY`、`STATE-RC6` 复核。宿主的对应实现见[工具循环](../src/features/chat/skill-generation.ts)和[上下文管理](CONTEXT_MANAGER.md)。

## HTTP 契约

工作区 API 前缀为 `/api/conversations/:id/workspace`，要求本人登录且会话已启用 Harness。类型和输入校验见 [types.ts](../src/features/harness/types.ts)、[workspace.ts](../src/features/harness/workspace.ts) 和 [routes.ts](../src/features/harness/routes.ts)。

| 方法与路径（相对前缀）                                    | 请求或结果                                                                                                                                          |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /`                                                   | 返回项目 ID、可见文档目录、相关访问记录、本人新偏好，以及同项目其他新会话的 ID 和标题                                                               |
| `GET /documents/:docId`、`GET /documents/:docId/versions` | 可选 `?version=N` 读取指定可见版本。版本列表仅返回该会话已获权的版本号                                                                              |
| `POST /documents`、`PATCH /documents/:docId`              | 新建使用 `{name,content,kind?}`，kind 可选 document 或 handoff；更新使用 `{baseVersion,content}`                                                    |
| `POST /publish`                                           | `{documentId,version,content?,references?}`，references 为最多 32 个用户明确选定的 `{documentId,version}`                                           |
| `GET /requests`、`POST /requests`                         | 列出本会话相关申请，或由目标会话提交 `{sourceConversationId,taskId,purpose,documentId?,version?}`。文件 ID 和版本一起提供，亦可都省略让来源会话选择 |
| `POST /requests/:requestId/decision`                      | `decision` 取 `approve` 或 `reject`，可另传 `documentId`、`version`。重复决定幂等，冲突返回 409                                                     |
| `POST /shares`                                            | 来源会话提交 `{targetConversationId,documentId,version}`，目标会话立即获得该固定版本的只读访问。                                                    |
| `POST /grants`                                            | 来源会话提交 `{targetConversationId,taskId,documentId,version,purpose}`。taskId 使用目标会话的助手消息 ID 或 `"next"`                               |
| `POST /preferences`、`PATCH /preferences/:prefId`         | 创建 `{content}`，更正 `{version,content}`                                                                                                          |
| `POST /preferences/:prefId/decision`                      | `version` 和 `decision`，后者取 `admit` 或 `withdraw`                                                                                               |

另有两个聊天操作。运行中通过 `POST /api/conversations/:id/steer` 发送 `{messageId,requestId,content}`。批准后可通过 `POST /api/conversations/:id/approvals/:approvalId/continue` 明确继续。普通模型工具只能申请访问和提议候选；发布、批准与长期纳入由用户操作。用户直接发送「同意申请 申请ID」「拒绝申请 申请ID」可指定申请。只有一个待处理申请时可以只说「同意」。预授权示例为「授权“B”的任务“下一次”读取“对比.md”v3，用途：核对方案」；发布示例为「发布“交接.md”v2到项目」。无法唯一确定请求或资料时在卡片中选择。
